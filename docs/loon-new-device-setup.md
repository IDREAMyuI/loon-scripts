# 新 iPhone / iPad 从零配置 Loon

> Last reviewed: 2026-11-12
>
> 适用于本仓库的 `config/Loon_Public_v2.conf`。以当前 main 为准；iPhone 和 iPad 使用相同步骤，按钮名称会随 Loon / 系统版本略有变化。下文用功能名称定位，不把未经核对的按钮位置当成固定界面。

## 先了解要恢复的四部分

| 部分 | 保存在哪里 | 新设备怎么获得 |
| --- | --- | --- |
| 分流、策略组、DNS、插件入口 | 本仓库公开主配置 | 从正式 URL 导入 |
| 机场原始订阅与 Sub-Store 处理步骤 | 旧设备本机 | 在新设备重建；需要相同节点时，对照旧设备的订阅与处理步骤 |
| MITM 证书及系统信任 | 每台设备本机 | 新设备重新生成、安装并完全信任 |
| 运行模式、策略组选项及应用全局开关 | Loon 本机状态 | 按本文核对，并与旧设备比较未确认的选项 |

**只导入公开主配置，不能自动得到旧手机的订阅、证书和全部应用设置。** 本文能恢复仓库定义的行为；旧手机未记录的本机选项要在第 8 节核对后，才能称为完全一致。不同设备可能因网络与节点健康状态不同，自动选到不同台湾节点，这是故障切换的正常结果。

最终目标：OpenAI 只走台湾；日常代理台湾优先，其次香港、最后日本；保留全部可导出的节点供手动选择；国内和局域网直连；仅既定 Apple 账号主机明确直连；启用正式插件。

## 1. 准备材料与安装

1. 在新设备的 App Store 安装 Loon；使用拥有购买记录且可下载该 App 的个人账号。App 的下载入口见 [Loon 官方说明](https://nsloon.app/docs/intro/)。
2. 准备自己的机场原始订阅地址，从服务商账户页面取得；不要把它发给公共转换网站。确认服务允许多设备及相应同时连接数。
3. 准备一条可用的台湾节点或服务商提供的 **Loon 原生节点订阅**，用于首次下载与初始化。如果当前网络可直接取得全部资源，可不使用临时节点；资源被网络阻断时再用它。
4. 旧手机暂时保留原配置。新设备连接可用网络；首次启动 Loon 时，如系统询问添加 VPN 配置，选择允许并用设备密码确认。

本教程只用官方 Sub-Store 在本机转换。公共主配置、官方插件链接可以公开；原始订阅、节点二维码、Sub-Store 数据备份、包含证书的本地配置不能公开。

## 2. 首次准备：先让 Sub-Store 可以工作

主配置从本机 Sub-Store 读取 `LoonNodes`，所以第一次不能指望“导入主配置”立即得到节点。推荐先在 Loon 自带的本地配置下完成本节，再切换正式主配置。

### 2.1 准备临时网络

1. 在 Loon 的配置管理中，保留并选中自带本地配置，把它标记为“初始化临时配置”，便于后面识别。
2. 如果需要代理才能下载资源，在其节点管理中使用“添加节点 / 扫码”导入服务商的台湾节点，或在“订阅节点”中添加服务商提供的 **Loon 原生节点订阅**并更新。选择台湾节点作为当前代理出口，测试能够连接。
3. 不要将机场完整配置直接覆盖到仓库的正式配置上。若订阅格式报错，不是改扩展名即可解决：先索取 Loon 原生节点输出，或用服务商的单节点二维码完成临时接入；也可从旧设备通过你自己的安全渠道取得可用单节点。
4. 无需向其他设备开放 Loon 的局域网代理，也不要假设旧手机开热点就能分享其 VPN 出口。

没有任何可用节点且网络又无法下载 GitHub / 前端资源时，应先解决这一下载条件，再继续；反复刷新空策略组不能完成初始化。

### 2.2 安装官方 Sub-Store 插件

1. 在临时配置的插件管理中，使用“从 URL 添加 / 安装插件”，粘贴：

   ```text
   https://raw.githubusercontent.com/sub-store-org/Sub-Store/master/config/Loon.plugin
   ```

2. 启用插件和脚本引擎。若插件安装时询问规则使用哪个代理策略，选择临时配置中已经可以工作的台湾策略；不要选择不存在的策略名称。
3. 在临时配置的编辑器中找到 `[Host]`，确保这一行存在；已有其他内容保留，不重复建立同名章节：

   ```ini
   [Host]
   sub.store = 127.0.0.1
   ```

4. 插件需要 MITM；先完成第 3 节的证书步骤，再开启 Loon 连接、打开 Sub-Store。

Sub-Store 官方说明指出 `sub.store` 不是其持有的公网域名。本项目将它映射到本机：如果插件没有接管，请求应失败，不应通过删除映射来“修复”。官方前端为 `https://sub-store.vercel.app`，应确认它连接的是当前设备的代理 App 后端，而非不明远程后端。参见 [官方域名安全说明](https://github.com/sub-store-org/Sub-Store#substore-domain-safety-notice)与[安装说明](https://sub-store-org.github.io/doc/guide/installation)。

## 3. 在新设备生成、安装并信任证书

1. 进入 Loon 的 MITM / 证书管理，**在新设备生成新的 CA 证书**。不要导入他人证书，也不需要复制旧手机私钥。
2. 选择安装证书，按 Loon 提示用 Safari 下载描述文件，允许下载。
3. 打开系统“设置”，进入“已下载描述文件”，或“通用 → VPN 与设备管理”，选中刚生成的 Loon 证书描述文件，按提示安装。
4. 再进入“设置 → 通用 → 关于本机 → 证书信任设置”，对刚安装的 Loon 根证书开启“完全信任”。iPad 同理。
5. 回到 Loon，确认 MITM **总开关**已启用，选中的证书与刚安装、信任的是同一张。HTTP/2 MITM 等子选项不能替代总开关；子选项具体值仍须对照旧设备，不从“过去曾排障”推断当前值。

“已安装描述文件”和“完全信任”是两步，缺一不可。更换本地配置后，要再次确认当前配置使用的证书仍是这张；如果没有沿用，就在正式配置中重新生成并完成安装与信任，不要把证书材料写回公开仓库。参见 [Apple 手动证书信任说明](https://support.apple.com/zh-cn/102390)及 [Loon MITM 文档](https://nsloon.app/docs/MitM/)。

## 4. 在本机 Sub-Store 建立 LoonNodes

### 4.1 打开本机管理界面

1. 保持 Loon 连接，官方插件、脚本和 MITM 均开启。
2. 用 Safari 打开 `https://sub.store`，这是官方插件配置的打开入口；如果打不开，先按第 10 节排查，不要删除 Host 映射。
3. 页面能进入且没有后端连接错误后，再填写订阅。若跳到官方前端，确认后端仍是这台设备的 Loon；不要选择陌生服务器后端。

### 4.2 添加单条订阅

1. 在“订阅”页面新建 **单条订阅**，输入自己的名称，例如 `MyAirport`；这里只是本机名称，可以自定。
2. 来源选择远程订阅 / URL，粘贴机场原始订阅地址，保存。
3. 预览或刷新，确认能解析出节点；至少应有可用台湾节点。其他地区可以保留。
4. 有多个订阅就分别建立。为了和旧手机完全一致，需要对照旧设备同一条订阅的处理步骤及顺序；不能把“新建设为空处理”当成旧设备原样恢复。
5. 新建时先不添加网上的测速、重命名或筛选脚本。不要删掉台湾节点，也不要只保留台湾／香港／日本，否则后面的手动组无法包含全部可导出节点。

### 4.3 转换后检查节点参数

在 Sub-Store 的 Loon 格式预览中核对协议类型及数量，再到 Loon 更新后做单节点连通性检查。数量以当前服务商输出为准，不把旧聊天里的历史数量当作必须恢复的目标。

- 如果服务商确实提供 VLESS Reality Vision，检查输出是否保留 `flow=xtls-rprx-vision`，以及服务商要求的传输、TLS、SNI 和 Reality 参数。普通 VLESS 不需要强行添加 Vision；参数丢失时先排查来源与转换，不手工猜值。
- 如果使用 Hysteria2，确认当前 Loon 支持且单节点可连接；不要把临时抓包时屏蔽 UDP 的操作搬到日常配置。不能仅凭“已解析出节点”判断实际连通。
- 节点预览含凭证，只在本机核对，不把整行复制进 Issue、PR 或公开截图。参见 [Loon 单节点文档](https://nsloon.app/docs/Node/)。

### 4.4 建立组合订阅

1. 新建 **组合订阅 / Collection**。
2. **名称（name）填写 `LoonNodes`，大小写完全一致。** 若界面同时有显示名称，只改显示名称不够；以输出路径中的 `LoonNodes` 为准。
3. 把刚建立的单条订阅加入组合并保存。即使只有一家机场，也建立组合，以匹配主配置的 `/collection/` 路径。
4. 预览组合，输出平台选 **Loon**；确认显示的是 Loon 可用节点，而不是整份 Clash YAML 或编码后的 URI 集合。不支持的协议不能仅靠格式转换变成 Loon 支持的协议。
5. 最终本机输出地址为：

   ```text
   https://sub.store/download/collection/LoonNodes?target=Loon
   ```

这个地址由**发起请求的当前设备**上的 Sub-Store 处理。旧手机建好了 `LoonNodes`，不等于新 iPad 也有数据；两台设备必须各自建立。

这里已经完成订阅转换，不需要再送到外部转换站。本项目最终订阅的资源解析器关闭，**不再叠加 Sub-Store-parser 或其他解析器**。参见官方[单条／组合订阅说明](https://sub-store-org.github.io/doc/subscription/overview)与[组合订阅步骤](https://sub-store-org.github.io/doc/subscription/collection)。

## 5. 导入并选中正式主配置

1. 在 Loon 配置管理中选择“从 URL 下载 / 导入远端配置”，输入以下地址；这一步导入的是**整份配置**，不是添加节点订阅：

   ```text
   https://raw.githubusercontent.com/IDREAMyuI/loon-scripts/main/config/Loon_Public_v2.conf
   ```

2. 为它起一个易识别的本机名称，例如“日常正式配置”，下载后选中为当前配置。`v2` 是主配置文件名，不代表多邻国插件仍是旧 V2。
3. 在当前配置中确认本机证书仍已选择并信任，脚本和 MITM 开启。正式配置已含第 2 节的 Host 安全映射和官方 Sub-Store 插件。
4. 如果应用保留了临时手动安装的 Sub-Store，检查当前生效列表：保留一份正式配置所需的官方插件，避免同一请求重复执行。临时配置暂留作排查，确认正式配置可用后再自行清理。
5. 更新插件及其脚本资源、远程规则，然后更新 `SubStore节点` 订阅。首次切换可能出现集合尚未就绪的下载失败，确认第 4 节后重试即可。
6. 确认该节点订阅 URL 是上面的本机输出，且**资源解析器关闭**。配置已经写有 `parser-enable=false`，不必重复添加相同订阅。
7. 查看节点数量不为 0；确认台湾／香港／日本筛选组正确。地区识别依赖节点名称：若台湾为空，检查名称是否包含“台湾／台灣／台北／Taipei／TW”等明确标记，再在本机 Sub-Store 调整对应名称。不要把香港节点改名冒充台湾。

**成功标志：** 当前配置为正式配置，`SubStore节点` 更新成功，台湾组非空，插件和远程规则下载成功。

## 6. 检查运行模式与策略组

运行模式选 **分流 / 规则模式**。不要将“日常代理”这个策略组误认为“全局代理模式”。策略组按下表核对：

| 项目 | 正常状态 | 含义 |
| --- | --- | --- |
| `代理模式` | 选择 `日常代理` | 日常默认；恢复后也要手动确认应用保存的选择 |
| `日常代理` | fallback，台湾 → 香港 → 日本 | 台湾不可用才尝试香港，再日本 |
| `ChatGPT台湾` | fallback，只含台湾节点 | 台湾全部失败时连接失败；不回退香港、日本或手动组 |
| `手动选择` | 含 `SubStore节点` 的全部可导出节点 | 临时指定普通代理出口时，先在这里选节点，再把 `代理模式` 切到它 |

手动切换只影响交给 `代理模式` 的普通代理流量。分流模式下，OpenAI 的规则仍单独交给 `ChatGPT台湾`。用完手动模式，记得把 `代理模式` 切回 `日常代理`。

Apple 账号服务的直连沿用仓库远程规则中的四个精确主机，不自行添加 `apple.com` 全域直连。具体主机以 [`rules/direct.list`](../rules/direct.list) 为准。

## 7. 检查插件和功能开关

当前主配置自动加载下列正式入口，不需要逐个手动导入脚本：

| 插件 | 来源 |
| --- | --- |
| Sub-Store | sub-store-org 官方 `config/Loon.plugin` |
| 掌阅 | 本仓库 main 的 `plugins/ireader_splash_ad.lpx` |
| 两步路 | 本仓库 main 的 `plugins/liangbulu_ads.lpx` |
| 微博 | 本仓库 main 的 `plugins/weibo_splash_ad.lpx` |
| 多邻国 | 本仓库 main 的 `plugins/duolingo_ads.lpx` |

确认插件已启用、脚本已下载。同一 App 只启用一份；不同时启用旧 V2、开发分支测试版和正式版。

- **脚本：开启。** Sub-Store 及自有插件依赖它。
- **MITM：开启。** 保留插件要求的精确主机与 `sub.store`，不添加 `*`。
- **主配置本地 Rewrite：关闭。** 当前 `[Rewrite] enable=false` 没有本地复写，不要照通用教程把所有功能开关全打开；插件依赖以各插件自己的声明为准。
- **服务器证书校验：保留。** `skip-server-cert-verify=false`；不要为解决证书安装问题改成跳过校验。
- **Sub-Store 同步 / Gist：本步骤不需要。** 本机转换无需 GitHub Token 或远程同步。默认插件带有定时同步任务，不等于已经配置了同步产物；不要为完成安装填写凭证或开启额外同步。

广告处理的当前范围、验证与限制见 [`CHANGELOG.md`](../CHANGELOG.md)。iPad App 版本或接口可能不同，手机上的一次成功不能保证 iPad 所有场景均有效。

## 8. 应用本身的选项：哪些已知，哪些要对照旧手机

下表“配置值”直接来自当前主配置，导入后检查生效值即可，不必额外改系统 DNS。

| 项目 | 仓库配置值 |
| --- | --- |
| IP 模式 / IPv6 虚拟接口 | `dual` / `auto` |
| DNS | `system,119.29.29.29,223.5.5.5` |
| DoH / DNS 劫持 | `https://dns.alidns.com/dns-query` / `*:53` |
| UDP 不支持时 | `REJECT`，不意外直连 |
| 订阅 UDP / Fast Open | `udp=true` / `fast-open=false` |
| 网络接口 | `auto` |
| 允许局域网设备使用代理 | 关闭，`allow-wifi-access=false` |
| 连通性检测超时 | 5 秒；策略组另有自身检测参数 |

### 8.1 DNS 页面还要核对的选项

旧聊天最新生成的总结列出了以下目标，可用于找回设置入口。它是回顾性总结，尚未获得对应旧设备截图或原始操作确认，**不等于已经确认当前手机采用了这些值**。

| 选项 | 总结中的建议值 | 核对方式与依据 |
| --- | --- | --- |
| 包括系统 DNS | 开启 | 本仓库 `dns-server` 包含 `system`；确认界面没有把它排除 |
| DNS 查询回退 / 回落 | 开启 | Loon 官方说明默认在加密 DNS 失败后回落到普通 DNS，App 页面可关闭；在旧手机核对是否改过 |
| DoH 路由 | 直连 | 当前主配置未单独固定此界面选项；先对照旧手机的有效设置，不把阿里 DoH 地址本身当成直连设置证明 |

DNS 查询回落与节点故障切换是两件事。DNS 回落不表示 OpenAI 可以换到香港或日本；分流策略仍为 `ChatGPT台湾`。技术依据见 [Loon DNS 查询回落](https://nsloon.app/docs/DNS/)。

### 8.2 其余本机选项

以下项目**没有在当前公开配置或已取得的旧聊天记录中确认旧手机的实际值**。为追求完全一致，请在两台设备的 Loon 设置中打开同名项，逐项对照；暂时找不到时保留新安装默认值，并记为“未核对”，不要声称已完整复制。

| 本机项目 | 恢复方式 |
| --- | --- |
| 按需连接、断开后自动连接 | 对照旧手机；这是连接行为，不由本仓库策略组决定 |
| 包含所有网络、排除本地网络等系统 VPN 选项 | 对照旧手机与当前版本支持情况；名称相似不等于与配置中的绕过路由相同 |
| 代理接管模式：TUN Only / HTTP Proxy & TUN | 对照旧手机；不把历史日志显示“Loon Tunnel”直接当成该选项的确认值 |
| HTTP/2、QUIC、额外 UDP/STUN 开关 | 对照旧手机；主配置未规定的选项不擅自开关 |
| 全局资源解析器、额外 DNS 或网络覆盖设置 | 检查是否覆盖主配置；本项目 `SubStore节点` 的解析器必须关闭 |
| 日志级别、自动清理、抓包开关 | 对照旧手机；日常使用无需为了安装长期启用 Debug 或抓包 |
| 自动更新频率、SSID 自动切换、其他插件 | 对照旧手机；不要额外启用使分流或当前配置自动改变的功能 |

可以把核对结果存为自己的私人清单：只记选项名和值，不记订阅地址、节点、证书或设备标识。旧聊天中的建议不等于当时已经实施，也不应覆盖当前仓库配置。若旧设备实际值与仓库约定冲突，先确认差异，不修改公共配置来掩盖差异。

## 9. 按顺序验收

1. **基础连通：** 开启 Loon，运行模式为分流；普通国内网页正常打开。查看连接记录，选定的国内和局域网请求应按对应规则直连。
2. **订阅：** 更新 `SubStore节点` 成功，台湾节点非空；手动组能看到组合输出的完整可用节点。若只显示三个地区，检查 Sub-Store 是否已提前过滤其他地区。
3. **普通代理：** 打开一个需要代理的普通网站，连接记录的最终节点在正常情况下是可用台湾节点；必要时可在手动组临时选节点排障，结束后切回日常代理。
4. **ChatGPT：** 正常打开 App / 网页，在连接记录中检查相关第一方请求匹配 `ChatGPT台湾`，最终为真实台湾节点。不能只凭首页显示或一次出口 IP 查询推断全部请求。台湾不可用时应排查台湾节点，不切换 OpenAI 到香港／日本或全局手动出口。
5. **账号服务：** 验证日常需要的 Apple 账号操作，保持四个精确账号主机直连；无需为了安装反复退出账号。
6. **插件：** 按正常方式使用已安装的 App。多邻国可完成一课，检查是否出现课后广告、结算与进度是否正常；其他 App 检查实际使用场景。不必专门抓包，也不把“脚本执行完成”当成广告已移除。
7. **托管更新：** 完成初始化并保留私有备份后，手动更新一次正式主配置，复查本机 Sub-Store 的单条订阅和 `LoonNodes` 仍在、`SubStore节点` 引用仍正确、节点能更新、证书仍已选中并信任、策略组选择仍符合预期。公开主配置已声明本机集合输出，不依赖保留手动添加的机场原始订阅；不要把原始订阅补进公开配置。若本机状态丢失，先记录版本与更新方式并恢复私有备份，不能未经分析就改变配置架构。
8. **网络变化：** Wi-Fi 断开重连；有蜂窝功能的设备再测试蜂窝网络。确认 Loon 仍连接、分流模式和 `代理模式` 选择符合预期。

首次新设备实际验收前，本文只经过仓库与官方文档核对，不标记为新设备实测通过。第 8 节未核对项补齐前，只能确认项目配置一致。

## 10. 常见卡点，按原因处理

| 现象 | 优先检查 |
| --- | --- |
| `sub.store` 打不开 / 本机连接被拒绝 | Loon 是否连接；插件脚本是否下载；MITM 和系统完全信任；Host 映射保留；当前配置是否实际加载插件。不要删映射去访问公网 |
| 前端打开但后端连接失败 | 是否使用官方前端且连接本机 Loon；官方插件版本与 CORS 来源是否匹配；不要改成允许任意来源来绕过 |
| 集合不存在 / 输出 404 | 是不是只建了单条订阅；组合的真实 name 是否精确为 `LoonNodes`；数据是否建在这台新设备 |
| 能预览但 Loon 导入报格式错误 | 输出 `target=Loon`；Loon 节点订阅的资源解析器关闭；没有误填前端网页地址、单条订阅路径或原始订阅 |
| 台湾组为空，ChatGPT 失败 | 节点名称地区标记、订阅有效期及协议支持；不扩大 OpenAI 备用范围 |
| 插件有条目但广告仍有 | 插件及脚本下载、脚本与 MITM 开关、证书一致且完全信任、是否重复插件、App 是否为不同接口。修改响应不会清除 App 本地缓存 |
| 配置导入后节点为空 / 首次资源下载失败 | 返回初始化临时配置，完成 Sub-Store 本机集合与下载条件，再切回正式配置更新 |
| 更新主配置后功能异常 | 重新确认当前配置、证书选择、策略组保存的选择和节点更新状态；保留私有备份，避免覆盖本机订阅和证书 |

出现问题时，先记录时间、使用的网络和现象；确需抓包再按 [`SECURITY.md`](../SECURITY.md) 处理，材料放仓库外。无需将原始订阅或私钥发给维护者。

## 11. 以后换设备与日常更新

- **换设备：** 本文从头做；在新设备重建本机 Sub-Store 与证书。相同的公开配置 URL 不会同步本机订阅数据库。
- **节点更新：** 更新 Sub-Store 来源／组合后，再刷新 Loon 的 `SubStore节点`；远程订阅可能有缓存，数据未变化时先查看官方缓存说明，不任意重装。
- **插件更新：** 更新正式插件及脚本资源，继续只保留一份。不要以为更新主配置就一定刷新了所有资源缓存。
- **主配置更新：** 先保留私有本地备份，更新公开配置后复查证书、订阅、模式与策略组。包括敏感材料的完整备份仅保存在自己的安全位置，不提交 GitHub。
- **不需要额外服务：** 本项目本机方案不要求购买转换服务、搭建服务器或创建 Gist 同步。两台设备独立维护订阅，后续要跨设备同步时再另行设计。

## 12. 旧聊天总结的适用边界

本次补充参考了旧聊天新生成的步骤总结，并与当前 main 和官方文档交叉核对。下列内容不能直接照搬：

- 日常代理仍写日本优先、香港备用：当前正式配置为台湾 → 香港 → 日本。
- Apple 全域直连：当前仅既定四个账号精确主机明确直连，不扩大到全部 Apple 服务。
- 仓库所有者末尾字母容易混淆，以及插件放在根目录的旧路径：本文已核对的 `IDREAMyuI/loon-scripts`、`plugins/`、`scripts/` 路径为准。
- 总结里的解析器文本字段与当前仓库写法不同：本教程只要求确认当前订阅的解析器关闭，不据此改动主配置参数。
- 历史节点数量、旧脚本日志示例、只提掌阅的插件清单：不能替代当前输出和正式插件列表。

总结还提及银行 App 的快捷指令自动关闭／恢复 VPN。这不是公开主配置的一部分，也没有从当前材料确认旧手机仍启用了哪些自动化。若要完整恢复，请在旧手机“快捷指令 → 自动化”中检查相关 App 的打开／关闭触发器、动作和立即运行状态，再单独确认需要迁移的条目。`DIRECT` 不等于系统 VPN 已断开；如果实际停用 Loon，台湾分流和广告脚本也随之停止，按需连接还可能重新连接，因此不能只复制自动化而不核对第 8 节。本文不默认新建自动化。
